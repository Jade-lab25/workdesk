# FocusDesk v35 优化记录

- 版本：v34 → v35（侧边栏底部可见版本号）
- 范围：仅改动 `focusdesk/index.html` 单文件；不涉及 achieve、summarydesk、导航页、部署配置；无新增依赖
- 数据层：完全复用现有 `State.records` / `saveLocal` / `addRecord` / `updateRecord` / `WB_Cloud` 同步链路，未新增 Supabase 表或字段

---

## 一、本轮改动清单

### 1. 今日页聚焦（今日重点 + 其他待处理）

- 今日页顶部新增「⭐ 今日重点」区，最多 3 项。
- 每条独立任务右侧新增星标按钮，可手动固定 / 取消重点；超过 3 项时 toast 拦截（「今日重点最多 3 项，请先取消一项」）。
- 用户未手动选择时，**按现有排序自动取前 3 项作为默认重点，纯渲染期行为，不写回任何数据**；手动固定的任务全部失效（完成/删除）时自动回退到默认选取。
- 其余未完成任务收入默认折叠的「其他待处理」（原生 `<details>`），不丢失任何条目；展开态仅保存在内存 `State.todayOtherOpen`，重渲染（如勾选完成）后保持，刷新页面回到默认折叠。
- 重点区与折叠区内条目共用同一个渲染函数 `renderTodayItemHTML`，原有的完成 / 开始 / 拆解子任务打卡操作完全不变。拆解叶子不是独立记录，不显示星标、不能被固定。

### 2. 逾期任务轻量清理

- 今日页「今天要处理」区块下方新增逾期清理区（无逾期任务时整块不渲染），按到期日升序列出全部逾期独立任务，支持多选。
- 三个批量动作：**改期到今天 / 改期到明天 / 标记完成**；不提供批量删除。
- 未勾选时 toast 拦截；执行前 `confirm` 弹窗明确显示影响条数与动作名。
- 逐条复用 `updateRecord`（本地 `saveLocal` + 防抖云推送），结束后统一 `renderAll()` 一次并 toast 反馈处理条数。

### 3. 目标卡片「下一步」

- 目标卡片（含今日页内嵌紧凑卡片）新增「下一步」胶囊：优先取首个未完成的拆解叶子（二级 children 优先、保持拆解顺序），没有拆解时取首个未完成的关联任务（按 `r.goal === 目标标题` 匹配、到期日排序）。
- 无下一步时按场景区分空态文案：拆解全部完成 / 关联任务全部完成 / 目标已完成 / 尚未拆解（引导先拆解第一项）。
- 只读取现有 `subtasks` 与关联任务数据，未改动任何目标进度计算函数。

### 4. 仪表盘逾期列表口径修正

- 逾期卡片只渲染前 8 条时，底部明确显示「仅展示前 8 条，共 N 条逾期任务」并提供「查看全部 N 条」按钮。
- 按钮复用现有只读详情弹层 `showDashPopup('overdue')`；弹层展示全量数据，与 KPI 总数、卡片列表同源（均取自 `DashStats.overdue`），不会让用户误以为只有 8 条。

### 5. 首次加载外部脚本报错修复

- 移除 head 中的 `<script src="/page/page_comm/inject.js">` 引用（该地址在部分环境返回 HTML，导致 `Unexpected token '<'`）。
- 未改动 Supabase CDN 引用、其他 supabase 相关代码与任何部署逻辑。

### 6. 版本号

- 侧边栏底部可见版本 `v34` → `v35`；代码内历史注释（如「v34 修复」）保持原样。

## 二、数据兼容方式（今日重点）

重点 id 列表不另建存储，沿用应用已有的**隐藏系统记录**约定（与 `__focusdesk_habits__` 同一模式）：

- 新增一条标题为 `__focusdesk_meta__` 的任务型记录，固定使用稳定 ID `focusdesk_meta`，`note` 字段存 JSON：`{ "focusIds": ["id1", "id2", "id3"] }`；双端首次同步前分别创建时也会收敛到同一条记录。
- 标题以 `__` 开头，所有视图经现有 `isRecordHidden()` 过滤，用户在任何列表 / 统计 / 日历中都看不到它；循环任务 reconcile（无 seriesId）、自动归档（仅处理已完成记录）均不会触碰它。
- 持久化完全走现有链路：`addRecord/updateRecord` → `saveLocal`（localStorage `wb_focusdesk_v1`）→ 在线时 `WB_Cloud.schedulePush`  upsert 到现有 `fd_tasks` 表，`note` 列在 `taskToRow/taskFromRow` 中原样往返；多端合并走现有 `mergeCloudRecords` 的 updatedAt 最后写入获胜（LWW）。
- 每次保存自动去重并剔除已不存在 / 已失效（完成、归档、删除）的 id；取消到 0 条时写入空列表，首次使用前若没有任何有效重点则根本不创建该记录，零数据侵入。
- 导出 / 导入备份会包含这条隐藏记录，恢复后重点选择随之恢复，无副作用。
- 旧版本客户端不识别该记录，但因 `__` 过滤规则早已存在，旧版只会把它当作普通隐藏记录忽略，不影响打开和使用。
- 兼容旧版已在双端生成的同 title、不同 ID 重复元数据：不删除历史行，读取与后续更新明确选择 `updatedAt`（缺失时回退 `createdAt`）最新的一条，时间相同则优先稳定 ID，继续保持整条记录的 LWW 语义。
- 新增重点时，3 项上限只统计仍存在且符合今日列表条件（逾期、今日到期或进行中）的独立任务；已完成、已归档、已删除、改期到非今日列表及重复 ID 不占名额，并在本次保存时清理。

## 四、已知限制 / 残留风险

1. 多端同时调整今日重点时，`__focusdesk_meta__` 是单条记录，按 updatedAt LWW 合并——后保存的一端整体覆盖另一端的选择，不会做 id 级合并（与应用内隐藏习惯记录的既有合并行为一致）。
2. 今日重点只支持独立任务记录；目标拆解叶子无法单独加星（它不是 `State.records` 中的独立记录，无 id 可存）。
3. 「其他待处理」折叠态刻意不持久化，刷新页面后恢复默认折叠。
4. 隐藏记录会出现在 `fd_tasks` 表与备份文件中（界面不可见）；若未来有直接读表的外部统计，需沿用 `title LIKE '__%'` 的过滤约定。
